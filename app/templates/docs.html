GitHub Insights API

Dashboard

POST /api/chat

Send JSON {"message":"How many PRs were merged in pallets/flask last 30 days?", "history":[]}. Responses include a reply, selected repository and period, and the tools and underlying data. The agent may ask for a repository or a more specific question. History is optional, limited to 12 user/assistant messages; it is supplied by the client, not stored. Only previous user messages are used to recover repository and date context; repeat the metric in follow-up questions. Period defaults to the last 30 completed UTC days. Specify two ISO dates or say "last N days" to override it. Model prose is not guaranteed to be accurate.

GET /api/tools/<name>

Direct access to each agent capability: issue_closures, pull_request_activity, review_activity, review_turnaround, merge_cycle_time, contributor_activity, activity_trends, labels_and_themes, work_distribution, release_activity and repository_context. Each uses the query parameters below.

Query parameters

The metrics, insights, and tool endpoints require repo=owner/name, start=YYYY-MM-DD, and end=YYYY-MM-DD. Dates are UTC, start inclusive and end exclusive, spanning 1–90 days. End must be today or earlier.

GET /api/metrics

Returns repository, date period, fetched_at, aggregate facts, ranked closers and source issues. Counts currently closed issues, excluding PRs, by closing actor (not author).

POST /api/insights

Uses the same query parameters, not a JSON body. Returns narrative, tentative hypothesis, subjective confidence, validated numeric evidence, model name and underlying metrics. Prose remains unverified.

GET /health

Checks SQLite availability. Upstreams are checked on use.

Errors

JSON {"detail": "message"}: 422 for invalid input or oversized scans, 404 for missing resources, 502 for rejected upstream responses or invalid model output, 503 for unavailable or rate-limited upstreams. Rate restrictions include Retry-After.

Metrics and insights are persistently cached for 900 seconds by default.
